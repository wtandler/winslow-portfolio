## The Problem

Enterprise change leaders get status reports from each program that disagree with each other and are often out of date. What they need to know is usually already in the decks, assessments, and meeting transcripts their teams produce, but nobody reads all of it, and status tools only answer the questions someone thinks to ask, so risks nobody asked about go unreported.

## The Product Decision

I designed Threadbase to report findings without waiting for a question. It reads the documents each program produces, combines them into one portfolio view, and shows what changed, what needs a decision, and where programs contradict each other. I built it on two rules:

1. **Evidence first.** Every material finding links to the source page it came from. Incomplete evidence is labeled incomplete, and the product separates a true all-clear from missing or stale data, so a failed extraction never shows up as zero issues.
2. **Human governance.** Disputed or incomplete findings route to people for judgment. Reviewers accept, edit, or reject with recorded reasons, and every decision remains auditable.

## What I Owned

Threadbase is an independent build, designed for the enterprise change portfolios I work in professionally. I own the product vision, the system design, the specification, the build direction, and the deployment.

## What Is Built

The core workflow is deployed on Azure. In production today:

1. Document ingestion with malware and credential scanning.
2. Claim extraction that records the source page for every claim.
3. A review queue for disputed or incomplete findings, ranked the same way on every run.
4. Publication gates that assign each finding a confidence band based on its evidence.
5. A leadership view that opens with what changed and what needs attention.

I am now building executive briefings and analysis across portfolios. A leader will be able to get from any finding to its source page in two clicks.

## Trust Controls

Four controls make every finding checkable:

- A finding publishes only after passing explicit gates, with a confidence band derived from its evidence.
- Identical documents always produce identical findings, so any run can be repeated and compared.
- Reporting periods, snapshots, and baselines are stored as records, so comparing the same two snapshots always returns the same list of changes.
- Every mutation to the portfolio state is audited, and relationship history is append-only.

## AI-Native Delivery

I write the specification before any code. It lists every guarantee the product makes, and each guarantee has at least one automated check that runs against a clean copy of the code and against the deployed system. Coding agents build to that specification. One command runs every check, and the CI pipeline runs the same command.

## Microsoft Ecosystem Fit

The platform runs on Azure Container Apps and PostgreSQL with Entra-based identity and managed identities throughout, with infrastructure as code in Bicep. Document understanding uses Azure AI Content Understanding, so dense corporate slides resolve into findings that still point at the exact source page.
